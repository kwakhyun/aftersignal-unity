# AFTERSIGNAL 1.1 · 첫 품질 기준 구간

중앙역의 대화 → 전력 복구 → 경비병 6명 전투 → 로프·기억 수집·재탐색으로 이어지는 약 70초 구간에 적용했다. 큰 효과보다 카메라, 표면의 명도, 접지, 검격의 접촉 시점과 적의 반응을 먼저 수정했다. 비교 자료는 `review.html`에서 정상·느린 재생, 소리 ON/OFF, 효과 OFF로 볼 수 있다.

**완료 범위는 첫 품질 구간과 공통 액션·표현 코드다.** 기존 네 씬을 유지했으며 웹 버전의 17개 맵, 확대 마을, 추가 캠페인은 이 차수에 구현하지 않았다. 최종 출시 품질 달성을 선언하지 않는다.

## 확인한 구성과 가정

| 확인된 사실 | 값 |
|---|---|
| 엔진 / 파이프라인 | Unity 6000.4.0f1, URP 17.4.0, `PC_RPAsset` / 3D Universal Renderer |
| 목표로 빌드한 플랫폼 | Windows x64, Mono 네이티브 플레이어 |
| 기준 화면 | PlayerSettings 1600 × 900, 창 모드, 크기 변경 가능 |
| 카메라 | Perspective, FOV 43°, X 기울기 10°, 기존 추적 카메라 |
| 공간 / 물리 | x 진행, z 깊이, y 높이. 3D CharacterController·Physics Raycast·충돌체 |
| 캐릭터 | 2D SpriteRenderer, URP 커스텀 cutout 셰이더, ZWrite와 깊이 검사 |
| 상태 / 입력 | 초 단위 자체 상태 전환, Input System 1.19, WASD·마우스, LateUpdate 카메라 |

정지 화면 두 차례 수정: **Cycle 1**은 간판과 표면을 정리했지만 검은 그림자와 청색 벽이 강했다. **Cycle 2**는 도기 알베도·환경광·그림자 강도·천장 그림자를 조정했다. 최종 캡처에서 강한 차가운 광택은 줄었지만, 반복적인 평면 벽과 빈 외곽은 남았다. 파티클을 늘려 이 문제를 감췄다고 처리하지 않는다.

## 프로젝트의 표현 원칙과 적용

3D 물리와 깊이 이동을 유지하면서 공간의 명도 단계, 경로의 가독성, 준비와 접촉의 리듬을 정리했다.

| 표현 원칙 | 적용한 구성 |
|---|---|
| 거리와 재질에 따른 명도 분리 | 도기·차가운 강철·작은 따뜻한 조명 분리 |
| 이동 경로를 읽을 수 있는 구조 | 기존 상층·경사로·승강장 구조를 유지하고 가장자리 표시 |
| 전투 공간의 시각적 여유 | 큰 간판 축소, 전투 바닥의 낮은 장식 밀도 |
| 자세와 접촉의 구분 | 6개 핵심 검격 포즈, 방향성 작은 접촉과 차등 경직 |

아래 시간은 **이 프로젝트에서 설정하고 테스트한 값**이다. UI는 현재 게임의 실제 정보 구조와 한국어 가독성을 기준으로 구성했다.

## 아트 기준과 구현 연결

**절제된 / 낡은 / 긴장된** 야간 철도 공간. 주조색은 잉크색 강철 `#0d171d`, 저채도 도기. 보조색 `#376d70`, 인물의 은백색 머리와 적갈색 스카프를 유지한다. 앵커·주인공 행동은 민트, 강조는 황동 `#c1a16e`, 위험은 붉은색과 텍스트·형태를 함께 사용한다.

- 어두운 인물 실루엣 뒤에는 중명도 벽, 발 주변에는 무광 바닥. 흰색은 머리·작은 접촉·필수 문자에 남긴다. 배경 전체의 네온화를 피했다.
- 기본 인물 약 2.2m, PPU 49, 정면 900px 화면 높이의 약 12–14%. 새 포즈는 224px 캔버스·공유 축척 .32·발 위치 (112,212), point·무압축·개별 PNG. 기존 96프레임은 유지했다.
- 검은 윤곽과 제한된 내부 명암을 유지하되, 조명 셰이더는 색을 완전히 지우지 않도록 환경광 반응을 제한한다. 그림자는 실제 바닥 raycast 위치에서 크기·불투명도가 높이에 따라 변한다.
- 시뮬레이션 좌표는 계속 실수 단위다. 카메라 기반 스프라이트 시각 위치만 정렬한다. 항상 맨 위 렌더링, 전체 저해상도 필터, 2D 물리 전환을 사용하지 않는다.
- 배경 도기는 bilinear+mip, 스프라이트는 point. 작은 캐릭터 픽셀과 바닥의 고주파 반사가 경쟁하지 않게 광택·Bloom을 낮췄다. 원본 전체 Import Settings를 바꾸지 않았다.
- 카메라 방향은 기존 10° 유지. 선행 이동은 ±2.4m 이내, 추적 SmoothDamp 160ms, 명중 충격은 130ms 이내·회전 없음. 물리나 HUD 위치를 흔들지 않는다.
- UI는 AfterSignal Sans KR, 1600×900 캔버스 기준 기존 코너 패널 유지. 체력 손실 지연 바, 숫자/목표 텍스트 갱신 주기 조정, 일시정지에서 흔들림·효과·후처리 조절.

| 시안의 변경 | 실제 에셋·Unity 적용 | 성능 위험 / 확인 |
|---|---|---|
| A·D 작아진 표지, 따뜻한 벽, 명확한 발과 HUD | `QualityPass`, 역 씬, 도기 PNG/재질, ContactShadow, UGUI | 소품 draw call·그림자 / 빌드 캡처·GPU 시간. 호출 수는 유효 측정 불가 |
| B 짧은 방향성 접촉, 적의 기울기 | SignalEffects shader/lines, EnemyBrain, WAV | 투명 겹침·소리 중첩 / 효과 OFF 비교·개수 상한 |
| C 힘 모으기→전진→복귀 | `Art/Hero/Quality/katana-00..05.png`, PixelActor, GameTuning | Resources 로드·프레임 흔들림 / 정렬·투명·실제 속도·접촉 테스트 |

`01-station-paintover-CONCEPT.png`는 실제 Before 화면에서 만든 목표 **시안**이다. 실제 결과는 `after/`에만 있다. `katana-generated-DRAFT.png`는 검수 전 생성 원본이며 직접 게임에서 재생하지 않는다. 초안의 가짜 체크 배경을 이미지 편집 도구로 크로마키 처리한 뒤, 6개 연결 성분을 같은 축척으로 정규화하고 hair/alpha/발 기준을 확인했다. 최종 PNG와 프레임 시트는 실제 임포트했다. 모든 무기의 새 원화를 완성했다고 간주하지 않는다.

## 공격 연출 시간과 규칙

| 무기 | 준비→접촉 / 판정 종료 / 총 시간 | 입력 버퍼 | 생존 명중 정지 / 경직 |
|---|---|---|---|
| 카타나 | 100 / 170 / 320ms | 140ms | 38 / 210ms |
| 중검 | 230 / 340 / 560ms | 140ms | 65 / 320ms |
| 권총 | 0 / 25 / 240ms, raycast 단발 | 140ms | 14 / 120ms |

카타나 표현 포즈: 0–40 / 40–90 / 90–120 / 120–195 / 195–275 / 275–320ms. 명중은 표현 프레임 인덱스가 아닌 경과 시간으로 판단한다. 20ms 이하의 로직 서브스텝과 접촉 구간 교차 검사로 렌더 프레임이 건너뛰어도 피해가 누락되지 않게 했다.

기존 피해·콤보·무기 해금·보스 특수 조건·저장 키는 유지했다. 카타나 36(세 번째 54), 중검 68, 권총 32. 공격 중 이동 배율 .45, 권총은 기존 이동 유지. 대시와 피격은 미확정 공격을 취소한다. 공격 회복 후 버퍼를 받아 기존 연속 공격을 잇는다. 별도 패링·새 전투 프레임워크는 만들지 않았다.

검격 접촉 구간 시작에 궤적과 휘두르기 소리를 재생한다. **명중 확정 → 피해·적의 반응 → 접촉 위치의 VFX·명중음 → 개별 정지·카메라 충격 → HUD** 순서다. 한 공격의 적/유리 집합으로 중복을 막는다. 헛스윙에 적 피격·명중음·히트스톱은 없다. 권총 발사 이펙트는 총구에서 항상 발생하고 명중 접촉과 구분된다.

히트스톱은 `Time.unscaledTime` 기반 개인 타이머다. Time.timeScale을 변경하지 않는다. 처치는 +18ms, 장갑에 막힌 일반 보스 타격에는 정지를 적용하지 않는다. 정지 중 입력 버퍼·UI·카메라·VFX·오디오는 계속되고 플레이어 및 살아 있는 피격 적의 동작은 잠깐 멈춘다. 일시정지는 원래 timeScale을 보존·복원하고 AudioSource를 Pause/UnPause 한다. 슬로모션 .5 중 일시정지 복귀와 히트스톱 중첩을 테스트했다.

VFX는 작은 중심 형태·방향 선·짧은 소멸을 사용하며 모든 층을 매번 켜지 않는다. line 120–170ms, 대시 잔상 130ms, Burst 수명 최대 1.1초. 동시 효과 오브젝트 64, Burst 48 이내, 개별 방출 최대 32. 완전한 풀링은 미적용이며 생성·파괴 비용은 여전히 최적화 대상이다.

## 소리·출처·권리

새 PCM WAV **64개**: 20종 사건 × 3변주 + 4개 8초 환경 루프. 44.1kHz, 실제 오디오 에셋. 검·중검 스윙과 명중, 권총 발사, 피격, 방어, 처치, 타일/금속 발소리, 착지, 점프, 대시, 로프 부착/해제, 스킬, 유리, UI 확인/취소/경고. 권총 명중은 가벼운 금속 접촉 뱅크를 공유한다. UI 경고 등 뱅크에 있다고 모든 개별 상황 연결이 완료된 것은 아니다.

`Tools/Build-QualityAssets.py`에 직접 작성한 결정적 DSP 합성식으로 제작했다. 외부 녹음이나 상업 게임 음원은 사용하지 않았다. 14 voice의 우선순위·발음 간격 제한, 사전 로드, 강한 사건에서 짧은 환경음 duck을 적용했다. 실제 녹음에서 클리핑을 수치 검사했다. 사람이 오디오 장치로 청취한 주관적 믹스 검수까지 완료했다고 주장하지 않는다.

새 검격 PNG·도기 알베도·페인트오버는 OpenAI 이미지 생성 도구로 이 프로젝트용 제작. 최종 PNG를 소스로 동봉하므로 런타임 생성 서비스는 필요 없다. 새 DSP·코드·셰이더·기하 디테일도 프로젝트용 제작물이다. 별도 유료 라이선스 에셋은 구매하지 않았다. 기존 그림/폰트·Unity 패키지의 조건은 `../ASSETS.md`와 동봉 라이선스를 따른다. 생성물의 권리 독점성이나 권리 심사 완료를 보증하는 문서는 아니다.

## 검증·재현·되돌리기

자동 검사 및 프레임 측정은 `verification.json`, 원본 JSON/XML은 `checks/`에 있다. 정상/효과 OFF/15Hz/120Hz 루트는 실제 ControlFrame 경계를 통해 기본 피해량과 적 체력을 유지한 채 수행했다. QA용 순간이동·적 체력 축소로 캠페인을 통과시키지 않았다. 단위 테스트에서만 충돌·시간 조건을 위한 위치 fixture를 사용한다.

최종 EditMode 14/14, PlayMode 16/16 통과. 릴리스 빌드 성공, 오류 0. Unity 패키지 경고 10개(Core의 테스트용 stripper 7개와 UGUI/Input System의 C# 경고 3개)는 남았다. 릴리스 실행 파일 전체 캠페인 4/4 통과: 일반 적 22명+보스 1명, 로프 8회, 코어 직격 3회, 에필로그 저장·대화, 오류 0. 대표 릴리스 구간에서도 로프 1회·기억 수집·재탐색을 별도로 확인했다. 네이티브 창으로 화면은 확인했으나 마지막 수동 연속 입력 QA는 Windows 보안 창 때문에 끝내지 못했다. Input System 가상 키보드·마우스 테스트와 자동 ControlFrame 루트가 사람의 장시간 입력감 검수를 대신하지는 않는다.

`review.html`의 파일 URL 자동 미리보기는 브라우저 보안 정책으로 차단되어 우회하지 않았다. HTML의 로컬 파일 참조를 정적으로 검사했고 이미지·영상은 개별 파일로 검토했다. 페이지 버튼·반응형 배치의 브라우저 실측은 미검증이다.

초기의 Windows GDI 녹화는 Unity 시작 화면만 남는 것을 발견해 증거에서 제외했다. 중간 After 녹화의 종료 RenderTexture 오류도 제외했다. 제공 영상은 수정된 URP 실제 카메라와 HUD를 연속 녹화한 버전이다. 영상 readback의 약 2MB/frame 할당을 일반 게임 비용으로 보고하지 않는다. 비디오 없는 측정도 간헐적 검증 PNG와 게임 오디오 수집 비용을 포함한다. 호스트의 다른 일반 작업이 있는 PC에서 얻은 관측값이며 최소 사양 인증이 아니다. GPU 세부 pass, draw call, 투명 픽셀 수, 장시간 메모리 누수, 모든 화면 비율은 미측정이다.

모든 행은 같은 PC의 대표 루트이고 에디터 게임 실행 수치가 아니다. 개발 빌드 전후의 프레임 시간 개선을 입증하지 못했으며 안정적인 60FPS 합격도 아니다. 제한 120은 실제 120FPS 도달을 뜻하지 않는다. 릴리스의 `ReleaseForeground`라는 로그 폴더명은 전면 측정 **시도**를 뜻한다. 실제로는 Windows 보안 대화상자가 게임 위에 남아 전면 상태를 보장하지 못했다. 자동 조작 도구에 이 시스템 창의 대상 ID가 노출되지 않아 수동 닫기를 요청했다. 원본 릴리스 로그의 GC 0은 0할당 합격 근거로 쓰지 않으며 요약에서는 미측정으로 표기한다. D3D11은 느려 채택하지 않았다. 소리·UI·타이밍 개선과 성능 합격은 별개다.

1. `PLAY.cmd`로 플레이. Esc에서 흔들림·효과·후처리 조절. 조작은 루트 README 참조.
2. `Tools/Build-Windows.ps1`는 개발 빌드, `-Release`는 릴리스 빌드. Unity 6000.4.0f1 필요. 엔진/파이프라인 변경 없음.
3. `Tools/Test-Project.ps1`로 프로젝트 EditMode/PlayMode 테스트. `-aftersignal-smoke` 인자는 네 씬 캠페인 QA.
4. 대표 루트: `python Tools/Record-Quality.py MyRun --no-video`. Python의 imageio-ffmpeg가 필요하다. 녹화는 `--no-video` 생략, `--effects-off`, `--fps 15`, `--fps 120`, `--d3d11` 선택. Python 의존성은 게임 실행에는 필요 없다.
5. 기존 씬의 국소 적용은 Unity 메뉴 `AFTERSIGNAL/Quality` 두 항목을 순서대로 실행. 고유 detail 루트로 중복 생성을 막는다. 일부 변경에 Undo가 있으나 모든 serialized 씬 변경의 일괄 Undo를 보증하지 않으므로 먼저 씬 백업. `Build authored scenes and settings`는 전체 원본 네 씬을 재생성하므로 편집 씬에 함부로 실행하지 않는다.
6. **되돌리기**: 에디터를 닫고 현재 프로젝트를 복사한 후 `rollback-v1.0-assets.zip`을 별도 폴더에 푼다. 가장 안전한 방법은 보존된 v1.0.0 전체 프로젝트 ZIP을 새 폴더에 열고 기존 PlayerPrefs를 그대로 사용하는 것이다. 부분 복원은 `changed-files.json`의 modified 파일을 백업으로 덮고, added 항목을 현재 프로젝트 밖으로 옮겨야 한다. 자동 삭제·일괄 초기화는 수행하지 않았다. .meta GUID와 기존 저장 키는 보존했다.
