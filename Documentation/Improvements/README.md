# 기능·UI/UX 개선 패스 · 2026-11-07

전체 검토에서 나온 개선점을 한 번에 반영한 작업 기록입니다. **Unity 에디터와 비공개 에셋이 없는 환경에서 작업했으므로 게임을 실행해 확인하지 못했습니다.** 아래 "검증" 절의 정적 검사만 통과했으며, 수치 밸런스와 화면 배치는 실제 플레이로 다시 확인해야 합니다.

## 바뀐 점

### HUD와 길 안내
- 카메라 뒤의 대상(데미지 숫자, 적 경고, 로프 앵커, SAFE 표시)이 화면 앞에 반전되어 그려지지 않습니다.
- 차량 조준·산소·군용 트럭·폭격기 표시(OnGUI)는 지도나 패널이 열려 있으면 숨깁니다. 스타일을 캐시하고 해상도·UI 크기에 맞춰 키우며 그림자를 넣었습니다(`Presentation/OverlayText.cs`).
- 우측 목표 패널은 도시에서 고정 조작 안내 대신 **추적 중인 의뢰와 현재 단계**를 보여 줍니다.
- 길 안내 거리는 도로 기준 하나로 통일했습니다. 상단 방향은 "앞쪽 ↑ / 오른쪽 →"처럼 시선 기준으로 표시합니다. "0 m 앞" 오류를 고쳤고, 걸을 때는 카메라가 아니라 실제 이동 방향으로 회전 안내를 계산합니다.
- 배경 없이 떠 있는 글자에 그림자를 넣고 최소 글자 크기를 키웠습니다. 도시에서는 ARCHIVE 00 표시를 숨깁니다.
- 운전 조작 안내는 탑승 후 8초(정지 중에는 계속) 전체를 보여 주고 이후 한 줄로 줄입니다. 차량 하차 키 안내를 F로 통일했습니다.
- 기본 조작 안내는 설정에 따라 항상 / 처음 10분 / 숨김으로 표시합니다.

### 입력과 설정
- 모든 조작이 `Resources/Controls.inputactions`의 액션입니다. 키보드·마우스와 **게임패드** 바인딩이 있고, **설정 → 키 설정**에서 키보드·마우스 버튼 동작(무기 1–7, 도시 전망 포함)을 바꿀 수 있습니다(`AFTERSIGNAL.Unity.Bindings`). 점프·상승, 대시·가속, 방어·하강, 로프·보조 무장은 한 줄에서 함께 바뀌고 같은 키를 고르면 경고합니다. 이동·시점과 게임패드 버튼은 고정입니다.
- 화면의 키 안내는 바뀐 키 또는 게임패드 버튼으로 자동 표시됩니다(`Player/KeyHints.cs`). 기본 키로 키보드를 쓰면 원래 문구 그대로입니다.
- 타이틀과 일시정지 메뉴가 같은 설정 화면(`Presentation/SettingsPanel.cs`)을 씁니다. 난이도, 음량 슬라이더 3개, 화면 모드, 해상도, 그래픽 품질, 프레임 제한, 수직 동기화, 화면 흔들림, 전투 효과, 후처리, 시점 감도, 상하 반전, UI 크기, 조작 안내, 대사 속도·자동 진행을 다룹니다.
- 일시정지 메뉴에 끼임 해제(마지막 안전 지점, 10초 대기, 메뉴에서 남은 시간 표시)와 실제 조작 목록을 넣었습니다. 설정을 닫으면 목록이 바뀐 키로 다시 만들어집니다. 사망 화면은 청구된 치료비를 보여 줍니다.
- 게임패드로 상점·일지·스토리 선택지를 고를 수 있습니다(첫 선택지 자동 선택, B로 닫기). 키보드는 숫자 1–7로 화면에 보이는 순서대로 고르며 선택지 앞에 키가 표시됩니다. 패드 무기 순환은 보유한 7칸 전체를 돌고 장착 무기 이름·배율도 함께 바뀝니다. 패드 L3는 운전 중 경적만, 도보에서 바이크 소환입니다. 투항(Y 길게)과 시점 초기화(도보 R3)에 패드 버튼을 넣었습니다.
- 설정 목록은 마우스 휠로 스크롤되고 ◀ ▶ 항목은 좌우 키로 값을 바꿉니다. 화면 모드·해상도는 적용된 값을 표시합니다. 음소거 전 음량은 재시작 뒤에도 유지됩니다.

### 대화와 메뉴
- 대사는 타이핑 효과로 나오며 첫 E로 즉시 완성, 다음 E로 넘깁니다. 선택지가 하나인 스토리 단계도 E로 진행합니다. 자동 진행 옵션과 **최근 대화 기록**(일지 첫 화면)이 있습니다.
- 대화창과 대화 패널을 줄여 화면을 덜 가립니다. 큰 패널(지도, 설정)은 UI 크기가 커도 화면 안에 맞춰집니다. 타이틀 화면은 원화 구도 때문에 1600×900 기준을 유지합니다.
- 같은 대사를 다시 열어도 타이핑과 자동 진행 타이머가 처음부터 시작합니다. 대화 기록은 한 페이지 3개이며 일지 본문을 휠로 스크롤할 수 있습니다. 새 게임이나 다른 슬롯에서는 기록이 비워집니다.
- 무기 상점은 같은 칸에 장착한 무기와 성능을 비교합니다(산탄총은 펠릿 수 포함). AI 답변을 기다리는 동안 보내기 버튼으로 취소할 수 있고, Enter는 보내기만 합니다.

### 저장
- 진행 기록은 `persistentDataPath/saves/slot1~3.json`의 **저장 슬롯 3개**에 저장합니다(`Save/SaveStore.cs`). 버전 번호, 원자적 쓰기, 직전 파일 `.bak` 백업, 읽기 실패 시 `.corrupt` 보관과 백업 복원, 2초 단위 쓰기 제한이 있습니다.
- 설정(음량, 그래픽, 키 바인딩, 난이도)은 기기 단위라 PlayerPrefs에 남습니다.
- 처음 실행할 때 기존 PlayerPrefs 진행 기록을 슬롯 1로 한 번 가져옵니다(`Save/LegacyKeys.cs`). 슬롯 1 파일이 실제로 써진 뒤에만 슬롯 폴더에 `legacy-import.done`을 남기므로, 저장이 억제된 진단 실행 중에 이전이 끝난 것으로 처리되지 않습니다. 이웃 호감도처럼 미리 나열할 수 없는 키는 처음 읽을 때 가져옵니다.
- 에디터는 `persistentDataPath/saves-editor`를 써서 빌드한 플레이어의 슬롯과 섞이지 않습니다. 본 파일이 없거나 깨지면 `.bak`/`.tmp` 중 최신 사본으로 복원합니다. 종료 중(`Application.quitting` 이후)의 저장은 바로 디스크에 씁니다. 슬롯 목록의 저장 시각은 파일에 기록된 시각입니다.
- `-title-smoke`, `-life-smoke`와 PlayMode 테스트는 임시 저장 폴더를 써서 실제 슬롯을 건드리지 않습니다.
- 새 게임은 고른 슬롯 전체를 지운 뒤 시작하므로 네 도시 챕터·스포츠 리그·차량 부품 등이 모두 초기화됩니다. 타이틀에 **불러오기**와 슬롯 선택이 생겼습니다.
- 무기 목록이 바뀌어도 구매 기록이 유지됩니다. 하루 단위 보상·금고·업무 기록은 날짜마다 새 키를 만들지 않으며, 새 게임이나 슬롯 전환 때 이전 진행의 금고·업무·숨은 의뢰 기록이 남지 않습니다.

### 캠페인
- 일지는 데이터 기준 "메인 X/33 · 서브 Y/22"를 표시하고 전체/진행 가능/완료 필터, 원래 페이지 복귀를 지원합니다.
- 메인 의뢰 32개를 대화·조사·전달·선택 단계와 섞었습니다(전투 99 → 69단계). main04·10·12·18·24에 선택이 있고 finale(main30)에서 결말이 갈립니다.
- 적 체력은 의뢰 순서에 따라 오르고 난이도 배율을 받습니다. 방어 임무는 방어선 수치가, 탈출 임무는 제한 시간과 추격대가 있으며 실패하면 단계를 다시 시작합니다. 전투는 도보·수배 없음·34 m 이내에서만 시작합니다.
- 퀘스트 ID 특수 처리와 초상 선택을 데이터 필드로 옮겼고, 네 도시 캠페인은 `Resources/Story/FourCityCampaign.json`에서 읽습니다. `Tools/validate-story.py`가 CI에서 두 파일을 검사합니다. 자세한 규칙은 [CHRONICLE](../CHRONICLE.md)을 확인하세요.

### 경제·수배·탈것
- 밸런스 수치를 `GameTuning`으로 모으고 난이도(쉬움/보통/어려움, `DifficultySettings`)를 추가했습니다.
- 출동 병력을 쓰러뜨려도 수배가 풀리지 않습니다. 교전 중인 경찰 로봇이 있으면 다음 지원 병력이 오지 않고, 쉬는 로봇과 하차를 마친 수송차는 철수해 로봇이 계속 쌓이지 않습니다. 난이도 피해 배율은 서하를 공격하는 모든 경찰·군·로봇·헬기·함포에 한 번씩만 적용됩니다. 사망 시 소지금의 10%(100–2,500 C) 치료비, 체포 시 예비 탄약 압수와 수배 수준에 비례한 보석금·벌금이 있습니다.
- 은행 금고는 7일, 상점 금고는 2일 재사용 대기와 낮아진 보상, 경보 수배가 있습니다. 연속 취침으로 날짜를 건너뛸 수 없습니다.
- 자연 회복은 체력 60%까지입니다. 회복 단말은 40 C로 완전 회복하고 예금은 하루 1%(상한 있음) 이자를 받습니다.
- 차는 정비소에서 등록한 차량만 내 차이며 커스텀도 그 차에만 적용됩니다. 정비소 수리는 차량 내구도를 100%로 되돌리고, 등록 후보는 방금 타고 온 차입니다. 업무 메뉴의 보수는 난이도 배율이 적용된 금액입니다. 호텔 객실 취침도 최소 깨어 있는 시간 규칙을 따릅니다. 충돌 시 바로 멈추지 않고 튕기거나 미끄러집니다.
- 맵 밖으로 떨어지면 마지막 안전 지점으로 돌아옵니다. 수배 중에는 로프 사거리가 60 m로 줄고, 시설 업무에 길게 누르기·운반 단계가 섞입니다.
- 수감 중 종료 후 이어하기가 탈옥으로 처리되던 문제를 고쳤습니다.

### AI 자유 대화
- 첫 대사는 로컬 대사로 만들어 열 때마다 유료 요청을 보내지 않습니다. 실패 응답은 대화 기록에 남기지 않습니다.
- 429는 자동 재시도, 503은 게이트웨이의 인물 대사, 연결 실패는 로컬 대사로 처리합니다. 세션 60회·대화당 20회 한도, 요청 간 1.1초 간격, 서버 18초·클라이언트 22초 제한, 답변 취소가 있습니다. 보내기 전에 닫거나 취소한 요청은 한도에서 빠지지 않고, 시설 이용 안내(로컬 답변)는 한도와 관계없이 답합니다.
- 시설 이름은 게임이 보내고 모델 출력의 태그·제어 문자를 제거합니다. 모델은 `NPC_MODEL`로 바꿀 수 있습니다. `Tools/test_npc_gateway.py`가 CI에서 실행됩니다.

## 검증
- C# Runtime 어셈블리를 Unity 참조 DLL과 Input System/URP 스텁으로 컴파일해 오류 0을 확인했습니다. 새 EditMode 테스트(`Tests/EditMode/SaveAndControlsTests.cs`, `SaveStoreTests.cs`)와 수정한 PlayMode 테스트(`GameplayTests`, `ResidenceTests`, Mirelo·음악·음성 재생 테스트)도 같은 방식으로 컴파일만 확인했습니다. Editor 어셈블리와 나머지 테스트는 컴파일하지 못했습니다.
- `python3 -m unittest Tools/test_npc_gateway.py`(20개), `python3 Tools/validate-story.py`, `node Tools/public-assets.cjs`가 통과합니다.
- 다중 에이전트 코드 리뷰와 반박 검증을 두 차례 거쳐 확인된 결함(1차 캠페인 12건, 2차 전체 40건과 추가 개선 항목)을 수정하고, 수정분을 다시 독립 검토했습니다.

## Unity에서 확인할 것
1. 에디터에서 EditMode·PlayMode 테스트와 기존 스모크(`-urban-smoke`, `-life-smoke`, `-title` 등)를 실행합니다. 의도된 동작 변경 때문에 `UrbanSmoke`의 "주차 차량 유지"처럼 기대값을 바꿔야 하는 검사가 있을 수 있습니다.
2. 1600×900·1920×1080·2560×1440과 UI 크기 3단계에서 HUD·설정·대화창 배치를 확인합니다.
3. 게임패드로 타이틀 → 설정 → 플레이 → 일시정지 흐름을 확인합니다.
4. 기존 PlayerPrefs 저장이 있는 PC에서 첫 실행 시 슬롯 1로 이전되는지 확인합니다. 이 브랜치의 이전 빌드를 실행해 `saves/slot1.json`이 이미 있는 개발 PC라면 슬롯 1은 그대로 두고, 이전 PlayerPrefs 진행을 비어 있는 슬롯 2 또는 3에 가져온 뒤 타이틀에 안내합니다.
5. 캠페인 방어선 감소율, 탈출 제한 시간, 경제 수치를 플레이로 조정합니다.
